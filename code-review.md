# Code Review: backend-test-task

## Общие замечания

Код в целом понятный и компактный. В проекте видно разделение ответственности: контроллеры, репозитории, view и модели.  
По условию ревью мы абстрагируемся от инфраструктуры (фреймворк, БД, Redis) и предполагаем, что базовая валидация реквестов делает фреймворк.

Основные проблемы, требующие правки:
- Контроллеры иногда используют get() для действий, которые должны быть POST.
- JsonResponse не реализован — контроллеры не работали.
- В ProductRepository были небезопасные SQL-выражения и неверные методы получения данных.
- Cart модель и использование корзины были не согласованы (в разных файлах ожидались разные конструкторы) — упрощено и сделано гибко.
- CartView неправильно рассчитывал `item.total` и делал N+1 запросы на продукты (N+1 допустим для тестового задания, но в продакшене надо batch).

## Что исправлено

### Controllers
- AddToCartController: метод переименован в post(), добавлена обработка отсутствия productUuid/quantity (но базовая валидация предполагается фреймворком), реализована логика увеличения количества вместо дублирования CartItem, сохранение корзины через CartManager.
- GetCartController: теперь возвращает 200 и текущее состояние корзины (даже если пустая).
- GetProductsController: берёт category из query params, возвращает 400 при отсутствии категории.

### Repository
- ProductRepository: переписан на prepared statements (fetchAssociative/fetchAllAssociative), типизированные исключения (RuntimeException), приведение типов в make().

### Domain
- Cart: сделан более гибким — customer и paymentMethod опциональны, добавлен findItemByProductUuid().
- CartItem: добавлен increaseQuantity() для увеличения количества.
- Customer: осталось без изменений (валидация полей предполагается фреймворком).

### View
- CartView: исправлен расчёт item.total (теперь это price * quantity), обработан nullable customer (если нет customer — поле customer = null).
- ProductsView: оставлен как есть, корректно формирует вывод.

### Миграции
- В миграции таблицы products рекомендуется заменить `float` на `DECIMAL(10,2)` для цены и добавить уникальный индекс по uuid; это рекоменд. — для тестового задания можно оставить как есть, но лучше поправить при дальнейшей работе.

## Общее замечание про валидацию и инфраструктуру
- Валидация полей (required, типы, допустимые значения) и общая обработка ошибок инфраструктуры (подключения к БД, Redis) предполагается внешней и не детализируется здесь. Я не добавлял повторную проверку email/имен и т.п., поскольку это входит в обязанности фреймворка по условию задания.

## Рекомендации 
- В продакшне убрать N+1 в CartView: заранее загрузить продукты по UUID у ProductRepository.
- Добавить unit-тесты для Cart (поведение add/find/increase) и для ProductRepository.
- Если нужен uniform API response, вынести генерацию JSON в общий helper или базовый контроллер.
